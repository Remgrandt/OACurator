# OA Curator 0.5.0

OA Curator 0.5.0 adds support for the stable OAA 1.0 format and automatically upgrades compatible older Collection folders when you open them.

- Import OAA 1.0 and legacy 0.1 archives, and export OAA 1.0 archives.
- Upgrade referenced Collection, Gallery, and Artwork manifests together on open, including folders containing a mixture of 0.1 and 1.0 manifests. Already-current manifests are left unchanged.
- Preserve original scans and manifest contents during upgrades, changing only the format version. Save a private metadata backup before replacing manifests, and recover interrupted upgrades when the Collection is reopened.
- Improve archive checks for malformed ZIP content, duplicate names and JSON keys, invalid metadata, unsafe paths, and processing limits. Validate completed exports before installing the output archive.
- Retain more imported metadata, external-site links, extension data, and attachment classifications within the documented preservation limits.
- Keep private metadata, extensions, and supporting attachments out of default public exports. Including private metadata opts into a private backup.

Older `.oaa` ZIP files are not modified. Export a new archive to obtain OAA 1.0 output. Keep upgrade backup files private because they contain your original collector metadata.

JPG, PNG, and TIFF remain the renderable image formats; other files remain supporting attachments. OAA support has documented capacity and preservation limits and does not guarantee an exact round trip of every archive field or unreferenced file.

See [opening older Collection folders](../user/portable-data-oaa.md#opening-older-collection-folders) and [OAA 1.0 implementation scope](../oaa-1.0-conformance.md) for details.
